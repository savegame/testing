# Resource hashes

**Status:** implemented (`core/Hash.h`).

Blackbox-era NFS keys almost everything by hash rather than by string.

## binHash (32-bit "bin memory hash")

**Sources:** `MaxHwoy/Nikki` `Hashing.BinHash` (MIT); identical in all
community tooling.

```
h = 0xFFFFFFFF
for each byte b:  h = h * 0x21 + b   (mod 2^32)
```

Used for: texture names, solid names, FE resource names, most chunk-level
name→resource references. The game hashes names in stored case (typically
upper-case); we do not case-fold — callers pass the exact key.

## VLT hashes (32/64-bit, Jenkins-style)

**Sources:** ported from `NFSTools/VaultLib` (MIT): `VLT32Hasher.cs`,
`VLT64Hasher.cs` (see THIRD_PARTY.md).

- 32-bit: Bob Jenkins lookup2 with seed `0xABCDEF00`.
- 64-bit: Jenkins lookup8-style with seed `0xABCDEF0011223344` and prime
  `0x9E3779B97F4A7C13` (MW's VLT database uses 64-bit keys).

Reference vectors for the unit tests are generated by an independent
transcription: `tests/tools/vlt_hash_reference.py`.
